2. The "Perfect" Backup Script
You don't want to stop the server to back it up. Since you're on Folia, you need a script that talks to the server console to "freeze" saving for a second so you get a clean copy.

Bash
#!/bin/bash
# Configuration
SERVER_DIR="/home/minecraft/server"
BACKUP_DIR="/mnt/backups"
DATE=$(date +%Y-%m-%d_%H-%M)

# 1. Tell Folia to stop saving to disk temporarily
screen -S minecraft -X stuff "save-off$(printf '\r')"
screen -S minecraft -X stuff "save-all flush$(printf '\r')"
sleep 5 # Give it time to finish writing

# 2. Compress the world folder
tar -czf $BACKUP_DIR/world_backup_$DATE.tar.gz $SERVER_DIR/world

# 3. Turn saving back on
screen -S minecraft -X stuff "save-on$(printf '\r')"

# 4. Delete backups older than 7 days to save space
find $BACKUP_DIR -type f -mtime +7 -name "*.gz" -delete
(Make it executable with chmod +x backup.sh)

how does a Ddos attack work?

Think of a DDoS (Distributed Denial of Service) attack like a crowded school hallway.

Imagine it's the end of the day, and everyone is trying to walk to their lockers. Normally, the hallway (the server) can handle 200 students walking at once. But suddenly, 10,000 strangers show up out of nowhere. They don't have lockers; they aren't even students. They are just standing there, blocking the way.

Because the hallway is so packed with these "fake" visitors, the actual students can't get to their lockers. The hallway isn't "broken," but it's denying service to the people who are supposed to be there.

The Technical Breakdown
A DDoS attack works in three main stages:

The Botnet: An attacker infects thousands of "zombie" computers/devices (IoT cameras, old laptops, etc.) with a virus. These infected devices form a Botnet.

The Command: The attacker sends a single command: "Everyone, ping this Minecraft server IP at the exact same time!"

The Flood: Your server is suddenly hit with millions of tiny requests per second (Gbps of data). The server spends all its "brainpower" (CPU and Bandwidth) trying to answer these fake requests, which causes it to lag out or crash for the real players.

How your Data Center stops it
Since you're using a professional data center, they have "Mitigation Hardware" (like a giant filter).

Traffic Scrubbing: All incoming data goes through a "scrubber."

The Filter: The scrubber is smart enough to see the difference between a Real Player (sending movement data) and a Bot (sending junk data).

The Result: The scrubber "drops" the junk data into the trash and only lets the "Real Player" data reach your Ryzen 9 7950X.

Types of Attacks the IT Admin might mention:
Attack Type	What it does
UDP Flood	Overwhelms the server with "connection-less" packets (common in Minecraft).
Layer 7 Attack	Targets specific game features (like a bot trying to "login" 5,000 times a second).
ICMP/Ping Flood	Just tries to drown the server in "Are you there?" messages.

If the IT Admin asks, "What if we get DDoSed?" you say:

"The data center we are using provides Stateful Inspection Filtering. It scrubs the traffic at the network edge, so the junk packets never even reach the server's CPU. Plus, we'll be using a TCP/UDP Shield or a Proxy, so the actual backend IP is never publicly exposed."

how does hardware level DDoS protection work?

Hardware-level DDoS protection is like having a security checkpoint located miles away from your house. By the time a "visitor" (data packet) gets to your front door (the server), they have already been scanned, verified, and cleared.

Instead of your CPU trying to figure out which data is good and which is bad, dedicated ASICs (Application-Specific Integrated Circuits) do the heavy lifting at the network's edge.

How it works (Step-by-Step)
Traffic Interception: All data destined for your Ryzen 9 7950X first passes through the Data Center’s edge routers.

The "Scrubbing" Center: The hardware (like an Arbor TMS or Corero SmartWall) analyzes the packets in nanoseconds. It looks for "signatures" of an attack—like thousands of requests coming from the same Botnet or malformed packets that don't follow the rules of the internet.

The Filter (The "Drop"): If the hardware detects junk data (a UDP flood or a SYN flood), it drops those packets immediately at the hardware level. They never even reach the server's operating system.

Clean Pipe: Only the "Clean Traffic" (your actual players) is allowed through the "pipe" to your server.

Why Hardware-Level is "King"
In a normal setup (Software Protection), the server’s CPU has to look at every packet. If 10 million packets hit the CPU at once, the CPU maxes out at 100% just trying to say "No" to them, which causes the server to crash.

Hardware-level protection is different because:

It’s External: The attack is blocked by the Data Center’s massive infrastructure before it even reaches your "small" server line.

Zero Latency: High-end hardware filters data at Terabit speeds. It’s so fast that your players won't even notice an attack is happening; their ping stays the same.

Protocol Specific: It can be tuned specifically for Minecraft (Java edition uses TCP, while Bedrock uses UDP). The hardware can be told: "Only allow these specific types of packets through; kill everything else."

whats an SRV record

Think of a Standard DNS Record (like an A Record) as a GPS coordinate that takes you to a building. An SRV Record (Service Record) is like a GPS coordinate that also tells you which specific door to enter and how important that door is.

In Minecraft, a server usually runs on a "Port" (the default is 25565). If your server doesn't have a Dedicated IP, it might have a random port like 25578. Without an SRV record, players would have to type play.alrabeeh.com:25578.

An SRV record hides that messy port number so they only have to type the name.

The 4 Parts of an SRV Record
When you set this up in your domain settings (like Cloudflare), you’ll fill in these four "instructions":

Service & Protocol: For Minecraft, this is always _minecraft and _tcp.

Priority & Weight: These tell the computer which "door" to try first if you have multiple servers. Usually, you just set these to 0.

Port: This is the big one. You enter the specific port Bloom Host gave you (e.g., 25565).

Target: This is the numerical IP or the "hidden" address of your Bloom Host server.

How the Connection Happens
Student types: play.alrabeeh.com into Minecraft.

Minecraft asks the Internet: "Hey, is there an SRV record for _minecraft._tcp.play.alrabeeh.com?"

The Internet answers: "Yes! Go to IP 123.45.67.89 and use Port 25565."

Minecraft connects: The student joins the game instantly without ever seeing the numbers.

Why the IT Admin will like this
It shows you aren't just "pointing a name at a number." It shows you understand Layer 7 Service Discovery.

Admin Flex: "I'm using an SRV record to map the service port to the hostname. This way, if we ever need to change the backend IP or move to a different node on Bloom Host, the students' connection info stays exactly the same. No one has to update their server list."

Does that make sense? It’s basically a "translator" that turns a simple name into a specific technical connection.
